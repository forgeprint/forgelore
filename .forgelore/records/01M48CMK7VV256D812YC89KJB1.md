The shell that ran the command has no process substitution: tee >(cmd) is a bashism and /bin/sh, dash and POSIX sh all stop at the opening paren. Read stdin into a variable instead, or run the command under bash on purpose. The same message also comes from an unquoted ( in a filename or an unbalanced paren in a function body, so read the second line the shell prints: it echoes the text it could not parse.
